## Причины и правки

- При полёте возле поверхности небесного тела один и тот же CCD-сегмент
  проверял повторяющиеся вершины корабля и выделял массив на треугольник.
  Повторно используется набор вершин исходного меша, а позиции концов
  сегмента рассчитываются один раз на срез вращения. На системе 0 в Release
  выделения уменьшились с 506 144 до 10 567 байт на тик.
- Дерево BVH остаётся индексом треугольников. В каждом срезе проекции
  полуосей дают тот же AABB, который раньше собирался из восьми вершин.
  Проверка разделяющих осей откладывает вычисление остальных осей до
  прохождения первых нормалей. Меши, импульсы и точность CCD сохранены.
- На тиках 10368–10373 исходного Debug-прогона NPC 5003 и 5018 входили
  в один слот ожидания станции №4. Максимум 269,028 мс, из них 248,134 мс
  занимала динамическая коллизия. Слоты разведены по высоте через каждые
  15 работников. Заход к занятому по разрешению причалу идёт сначала
  над станцией, затем по оси порта.
- Разделение траекторий меняет момент стыковки и число доставок в фиксированном
  окне. Даже самый населённый сценарий продолжал выполнять доставки. Для
  динамики торговых маршрутов сохранено отдельное длительное испытание.
- Редкие тики свыше 50 мс остались. Прямой упор нескольких кораблей в
  станцию остаётся тяжёлым сценарием точной геометрии. В раннем нагрузочном
  прогоне с 4 UDP-клиентами, направившими тягу прямо в станцию, p95 достиг 89,67 мс,
  максимум — 694,41 мс. Этот замер был до правки маршрутов NPC и сделан с
  агрессивным сценарием, отличным от стандартного отхода.

## Воспроизведение

```bash
dotnet build IndifferentStars.slnx -c Release
dotnet test IndifferentStars.slnx -c Release --no-build
dotnet run -c Release --project tools/IndifferentStars.Diagnostics -- --life 12000 20261101 0
dotnet run -c Debug --project tools/IndifferentStars.Diagnostics -- --life 12000 20261125 0
dotnet run -c Release --project tools/IndifferentStars.Diagnostics -- --network 1200 4 20261101 7
```

`--life` принимает число тиков, seed и индекс системы. `--network`
принимает число тиков, число клиентов, seed, индекс системы и опциональный
`station-approach` для движения к станции. Синтетические клиенты используют
независимые сокеты, обычный handshake, управляющие команды и сетевые снимки.
Их метрика охватывает шаг мира. Отправка снимков измеряется косвенно по
числу принятых кадров состояния.

В Release прошли 200/200 .NET-тестов, включая регрессию разведённых слотов,
непрерывные столкновения на больших скоростях, отверстия в меше, стыковку,
экономику NPC и два независимых клиента. Прошли 11 сценариев запуска клиента,
`ShipTrackChecks` и `CruiseCoastChecks`. Прямой вызов headless-импорта повторил
известный сбой завершения редактора Godot. Проверки игровых ресурсов и сцен
выполняются запуском движка.

В итоговом Debug-прогоне исходной системы p99 снизился с 27,915 до
5,759 мс, максимум — с 269,028 до 48,952 мс. В двух других итоговых
Debug-прогонах было по одному превышению 50 мс. Сопоставимые прогоны без
изменения маршрутов давали одинаковые итоговые счётчики доставок.
Маршрутная правка в итоговых прогонах увеличивает путь к причалу, поэтому
при оценке результата отдельно приведены количества доставок.

| 2 | 19 | 1200 | 0,607 | 1,982 | 3,567 | 63,960 | 1 | 1186 |
| 4 | 39 | 1200 | 1,252 | 3,917 | 5,165 | 44,490 | 0 | 1184 |

Release, оба теста отправляли ввод для отхода от станции. Все клиенты
получили собственный ID, поддерживали движение и видели итоговые снимки.
При длительном контакте нескольких кораблей с геометрией станции остаётся
риск тяжёлых тиков.

Сцена `PopulatedSpaceChecks` прошла на RX 580, Forward+, 1280×720
с двумя независимыми клиентами. Зафиксированы сближение с NPC на 208,3 м,
сенсорные контакты, переключение транспондера, F1/F2/F3, 100/200/500 км/с,
сохранение инерции, полная остановка и маршрут к дальнему контакту.
На 500 км/с измерено 60 кадров, максимальное отношение шага к ожидаемому
по времени кадра и скорости — 1,053. Повторный запуск шёл с общим
тайм-аутом 250 секунд. Рендерер Xvfb с llvmpipe оказался слишком медленным
для проверки подключения сцены, поэтому итоговый прогон использовал RX 580.
