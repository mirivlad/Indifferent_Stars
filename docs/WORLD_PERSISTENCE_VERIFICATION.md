# Проверка сохранения мира (015)

Сохранение включает seed, индекс системы, версию генератора, игровое время,
следующий ID, состояние NPC и игроков, склады, трюмы, кредиты, навигацию,
варп, причалы, остатки залежей и последние 128 событий, включая сделки.
Случайность NPC восстанавливается из seed, идентификаторов и счётчиков
завершённых работ. Постоянного генератора со скрытым курсором у симуляции нет.

Один локальный JSON-файл формата v1 содержит состояние вместе с SHA-256.
Сервер берёт эксклюзивную блокировку, записывает временный файл рядом с
основным, сбрасывает данные на диск и заменяет файл атомарно. Резервная копия
содержит предыдущую корректную версию. Сервер восстанавливается из копии при
повреждении основной и завершает запуск с ошибкой при несовместимом формате,
генераторе или системе. Ошибка записи завершает сервер до подтверждения сделки.
Успешная покупка, продажа и её номер сохраняются в одном контрольном снимке.
Повтор того же запроса возвращает сохранённый результат.

Обычные изменения сохраняются каждые 30 с, при подключении и выходе игрока,
при Ctrl+C и SIGTERM. После аварийного завершения полёт и работа NPC
возобновляются с контрольной точки. Между снимками может потеряться до
30 с обычного полёта. После повреждения основного файла восстанавливается
более ранняя целая копия, включая её состояние торговли.

В протоколе v23 клиент подтверждает владение ключом ECDSA P-256. Вызов
привязан к серверу, UDP-адресу, профилю, сессии и короткому интервалу.
Ключ хранится локально в `user://profiles` с правами 0600 на Linux.
Адрес и порт выбирают файл профиля. Позывной только отображается в игре.
Приватный ключ требуется для доступа к сохранённому персонажу, поэтому для
переноса персонажа сохраняйте файл ключа. Снимки и остальные UDP-команды
передаются открытым текстом. При подключении через общую сеть используйте
существующий защищённый туннель.

Отключённый корабль приостанавливается. Положение, скорость и ориентация
возвращаются с тем же ID. Отданный другому кораблю причал остаётся занят:
капитан восстанавливается в безопасной зоне ожидания. Офлайн-экипаж не
получает тягу от последнего пакета. Активный варп продолжает оставшуюся
часть пути после входа с повторной проверкой безопасности.

## Запуск и проверки

Release: 204/204 тестов. Сборки решения и Godot-клиента без предупреждений.

```bash
tools/run-server.sh --bind 127.0.0.1 --port 17893 --save ./local-world.save
tools/run-client.sh --server 127.0.0.1:17893
dotnet test IndifferentStars.slnx -c Release
godot-dotnet --headless --path client --script res://tools/verify_resources.gd -- --record
IS_SERVER=127.0.0.1:17893 godot-dotnet --headless --path client res://tests/PersistenceChecks.tscn
```

- Два независимых UDP-пилота с одинаковым позывным получили разные ID.
  Повтор подписанного ответа с другого порта потребовал новый вызов.
- Первый пилот прошёл реальную стыковку и купил груз. Второй в момент сбоя
  летел со скоростью выше 20 м/с и креном. После принудительного завершения
  отдельного процесса первый вернулся на причал, второй вернулся в полёт с
  прежним ID и сохранённой ориентацией. Повтор покупки сохранил баланс,
  груз и склад. Из новой сессии прошла последующая продажа.
- Проверены резервная копия после испорченного основного файла, отказ
  второму процессу писать тот же мир и отказ при смене seed. После
  восстановления NPC прошли 50 тиков с совпавшими позициями, скоростями
  и фазами работы.
- Два запуска Godot с одной изолированной папкой и разными позывными
  вернули корабль #10000. Между запусками сервер штатно завершился по
  SIGTERM. Время сервера продолжилось с сохранённого значения.
